The problem

Single-stage RAG answers the easy questions and quietly fabricates the hard ones. Anything needing two hops (find the policy, then find the exception to it) falls apart, because one similarity search over one index can't plan. I wanted a system that decides how to retrieve before it retrieves.

What I built

A LangGraph agent over 10,000+ documents embedded in FAISS. Retrieval is hybrid: dense vectors for semantics, sparse keyword matching for the exact identifiers embeddings smear, fused and then dynamically re-ranked and contextually compressed so the model receives the tightest possible evidence set. Model Context Protocol gives the agent structured tool-use, so it can route a query into specialized sub-pipelines and chain several reads instead of guessing from one. Prompting is systematic rather than ad hoc: chain-of-thought for reasoning steps, ReAct for tool selection, few-shot exemplars for output shape.

The outcome

Multi-hop question accuracy improved 28% over single-stage retrieval, hallucination dropped 35%, and answer relevance held above 90% on the evaluation set. It runs as a FastAPI microservice, containerized with Docker on AWS EC2, so the numbers come from a deployed service, not a notebook.

The problem

A live conversational assistant has two failure modes a demo never shows: the context window fills up mid-session, and the model provider has a bad minute. Both look identical to the user: the product stops working.

What I built

A production GenAI application on LangChain and the Groq API with role-based prompt routing, a distinct system prompt per use case rather than one prompt trying to be everything, plus dynamic templates, session memory, and token-budget management that compresses conversation history before it overflows, preserving coherence across long multi-turn sessions. Underneath sits a deterministic fallback layer: when the model call fails or times out, the app degrades to a rule-based response instead of an error.

The outcome

Iterative LLM evaluation on prompt strategies, tuning chain-of-thought templates and fallback triggers, landed sub-five-second generation latency with consistent output quality across diverse inputs, and zero hard failures visible to the user.

The problem

Diagnostic ML papers usually optimize one model for one disease. A clinic doesn't work that way, and four conditions across three data modalities (tabular vitals, chest radiographs, MRI) can't share one preprocessing path without one of them getting worse.

What I built

Five-plus ML classifiers deployed behind a Flask REST API for real-time diagnosis across heart disease, diabetes, pneumonia and brain tumors. Each model runs an independent preprocessing pipeline with modality-specific normalization and feature engineering, and the inference architecture is modular so any single model can be retrained and swapped without downtime. Cross-validation and hyperparameter tuning workflows compare performance across datasets systematically rather than anecdotally.

The outcome

A 20–25% accuracy improvement across 1,000+ patient cases through rigorous benchmarking, with the modular design enabling rapid iteration. The research was published in Springer Nature.

Three peer-reviewed papers, plus eight months in a national lab

Two in Springer Nature, one in IEEE Xplore. All three were written during my B.Tech, all three built as working systems before they were written up.

A Holistic Disease Prediction System with Machine Learning

Most diagnostic ML papers optimize one model for one disease. This one argues for the opposite: a single deployable system covering four conditions across three data modalities (tabular clinical measurements for heart disease and diabetes, chest radiographs for pneumonia, MRI for brain tumors), each with an independent preprocessing and inference path.

My contribution was the model comparison and the serving architecture: benchmarking 5+ classifiers per condition under cross-validation, then deploying the winners behind a Flask API that supports real-time prediction and independent model updates. Validated over 1,000+ patient cases at a 20–25% accuracy improvement over conventional approaches.

Springer Nature Applied ML · Healthcare

Food Categorizer: EfficientNet-B1 Enhanced CNN for Food Classification on Food-101

A controlled study of transfer learning on a large fine-grained recognition problem: 101,000 images, 101 classes, high intra-class variance and low inter-class separation. The paper measures what a pretrained EfficientNet-B1 backbone plus targeted augmentation actually buys over a comparably tuned CNN trained from scratch.

Result: 87% classification accuracy with a 30% reduction in training time, evidence that the compute savings scale with dataset size, which matters for downstream applications like dietary assessment where retraining is routine.

Springer Nature Deep learning · Vision

Hybrid Lane Detection Combining SCNN, Canny Edge Detection and Hough Transform

Autonomous driving needs lane detection that is simultaneously robust and real-time, two requirements that pull in opposite directions. The paper proposes a hybrid: a spatial CNN supplies structural understanding of lane continuity where markings are degraded, while classical Canny edge detection and the Hough transform recover exact line geometry cheaply.

Evaluated on 1,000+ road images under adverse lighting and worn-marking conditions, the pipeline reached 95% lane-identification accuracy, a 20% reliability gain on baseline, while sustaining 30+ FPS inference.

Lab work · Physical Research Laboratory

Eight months of climate research on cloud–precipitation coupling across four Indian regions, using six years of ERA5 reanalysis (2019–2024): low cloud cover, cloud base height and cloud water vapour against observed precipitation. I built the ingestion and feature-extraction layer over millions of records in Python, MATLAB and xarray, then trained six model families (ANN, CNN-LSTM, Random Forest, XGBoost, LightGBM, AutoML) for rainfall classification and precipitation prediction.
